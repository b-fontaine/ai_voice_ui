# 009 — Plan technique

## Amendements de la revue du plan (A1 à A8, prioritaires sur le reste du document)
- **A1 — Mise en page de la 5ᵉ surface (pdr-0065 D7)** : `actions` est un **bandeau dédié sous la grille 2×2**, hors de la grille : les quatre surfaces de l'acte 1 ne changent ni de position ni de parent (S-02 de la fiche reste intact, sans l'assouplir). `CanvasBoard` devient stable : un parent unique pour les quatre cellules, bandeau frère de la grille ; test d'abord (T17) : à l'arrivée de `actions`, les quatre surfaces gardent le même `State` et la même position. Capture `app-smoke` de la fin de l'acte 2 (5 surfaces, texte ≥ 24 px) ; `act2-replay.jsonl` régénéré avec `act2-actions`.
- **A2 — Régressions de 008 à corriger dans le même pas (T06, avant T10)** : `delivery/views_test.go` (un message attendu, `updateDataModel` seul) ; `orchestrator/acceptance/genesis_agents_test.go` (`genesisComponents` lu dans `catalog.json`, plus en constante) ; `act2_transform_test.go`, `act2_shared_canvas_test.go` (assertion « zéro `createSurface` » restreinte aux quatre surfaces de l'acte 1, jamais supprimée) ; `backend/check-compose.sh` (`A2UI_COMPONENTS` du compose = `components` de `catalog.json`) donc **`docker-compose.yaml` modifié par la session principale dans T02** (`A2UI_COMPONENTS` à 5, `VOICE_*`) ; `genesis_catalog_test.dart` (items du catalogue = `GenesisContract.components` : `actionBarItem` ajouté dès T02, ou test déplacé dans la tâche de l'item). Ordre des messages de Livraison à l'acte 2 : mutation de la checklist d'abord, puis la surface `actions`. Cas C2 en échec : `actions` refusée → Livraison `failed`, compensation `deleteSurface(actions)` seule, mutation de la checklist conservée, phrase d'échec partiel.
- **A3 — Voix hors délégation (pdr-0065 D5 amendé)** : le SDK openai-go v3.90.0 documente `delegation_id` « required, nullable : null pour le contexte général de la session » pour `commentary.append` ; pdr-0052 impose une session par acte, donc la session de l'acte 3 n'a en général **aucune délégation**. Ordre : (1) `commentary.append` avec `delegation_id: null` ; (2) **seulement sur erreur d'acquittement**, `commentary.append` rattaché à la dernière délégation si elle existe ; (3) `instructions.append` en dernier, avec un texte **propre à l'orchestrateur** (`phrases.fr.json`, jamais le résumé de l'agent : canal de confiance, donnée non fiable). **Jamais de second envoi sur silence** (la voix pourrait dire deux fois la confirmation) : l'attente d'un transcript sortant ne sert qu'à observer (Q-75, journal), asynchrone, suivie par le `wg` de session, sans effet sur l'envoi. La politique vit dans la couche app ; l'adaptateur n'expose que des primitives (`AppendGeneralCommentary`, `AppendInstructions`, avec acquittement `instructions.appended` résolu par `route()`). Tous les faux `Sideband`/`VoiceReply` sont mis à jour.
- **A4 — `Manager.Act` atomique, intégré au Runner** : `Act(ctx, name, surface) error` sous `Canvas.mu` (ordre `Canvas.mu` → `m.mu` → `session.mu`) : refus si `running > 0` ou si une session ouverte est occupée ; session cible = numéro d'ouverture le plus grand ; `pending++` puis mise en file sous le verrou ; `Delegation` reçoit un champ `Action *ActionCall` (mêmes `work`, `pending`/`enter`/`leave`/`seal`, `GenericDone` nil). L'identifiant `act-n` (compteur atomique du Manager) n'entre jamais dans `seen` et n'est **jamais** passé à `AppendCommentary` : sur ce chemin, toutes les phrases passent par l'annonce. Sentinelles dans `internal/port` (`ErrNoSession`, `ErrUnknownAction`, `ErrCanvasBusy`) lues par `httpapi` via une interface consommateur (comme `CanvasResetter`). Le travail ne dépend jamais de `r.Context()`.
- **A5 — Validation synchrone, sans réseau (D1, D4)** : regex `^[a-z][a-z_]{0,39}$`, puis `action:<nom>` ∈ `LastTags()` d'un agent, puis surface active **et** possédée par ce même agent (`Registry.ActiveFor(owner)`), sinon 422 avant 202. Le message A2A ne porte que `{name}` + `activeSurfaces` lues dans le registre (la surface du client ne part pas à l'agent) et **une part texte** (a2a-go refuse un message sans part ; texte = nom de l'action). Dans `Run`, les cartes sont relues : tag disparu → `failed` honnête. Noyau d'agent : toute `genesis/action` absente des tags du profil → `rejected` avant le composeur (testé sur les trois agents) ; branche action de Livraison : `rejected` si `checklist` ∉ `ActiveSurfaces`. Corps HTTP strict (`DisallowUnknownFields`, une seule valeur JSON, deux chaînes non vides). `TagPlanner` : un tag `action:*` ne retient jamais un agent sur une demande vocale (test).
- **A6 — Boutons inactifs jusqu'au résultat (D6)** : le 202 revient avant le travail de l'agent. `CanvasActionBloc` : états scellés `Idle | Sending | Running | Failed` ; `Running` dure jusqu'à `ActionActivityChanged(busy: false)` (événement ajouté par `GenesisCanvasPage` depuis `AgentActivityBloc`, les slices ne se lisent pas entre elles), la fermeture de session ou un délai injecté. Le client HTTP fait **un seul essai** et rend un résultat scellé (`accepted`, `busy`, `noSession`, `rejected`, `failed`) ; le réessai borné vit dans le Bloc, réglages injectés (comme `canvasResetRetries`), sous `droppable`. `_resetStage` réinitialise le Bloc d'action. `ActionBar` lit la disponibilité par un `InheritedWidget` interne à la slice. L'`ActionDelegate` utilise `genUiContext.surfaceId` et ne gère que l'ensemble fermé d'actions ; un identifiant inconnu donne l'état neutre (RG-10). Vérifié : `Surface` accepte bien un `actionDelegate` en genui 0.10.4.
- **A7 — Découpage** : T16 avant T15, sans `[P]` entre eux (même slice `features/canvas`) ; `catalog_shelf` : « 5 / 6 » se calcule déjà sur `catalogComponents`, un test seulement ; T05 est un test de garde (genui notifie les ancêtres sur écriture d'un sous-chemin) ; le README du contrat documente l'exception de sous-chemin (seul `/checklist/decisionStatus`, pdr-0065 D3 contre pdr-0064 D1).
- **A8 — Phrases et limite** : `ActionResultTemplate` dédié et validé dans `phrases.fr.json` (le `ResultTemplate` des délégations ferait dire « Voici ce que je constate : « … » ») ; résumé nettoyé par `sanitizeSummary`. **Limite consignée** : une demande vocale ultérieure (« plutôt iOS ») fait réécrire tout `/checklist` par l'agent sans état, avec « En attente de décision » : la décision « Bloquée » est perdue sans bruit ; un test la décrit ; **Q-76** ouverte pour le porteur.

## Contrats
> **Section partiellement obsolète (revue du plan A1-A8, revue du code R10).** Les amendements en tête de ce document et le code livré prévalent. Écarts connus : le clic passe par un `ActionDelegate` (`Surface` le propose avant tout envoi à un LLM) et non par `dispatchEvent` seul ; le message A2A de l'action ne porte que `{name}` et `activeSurfaces` (la surface du client n'est jamais relayée à l'agent) avec une part texte égale au nom de l'action ; la voix est `VoiceReply.Announce` (politique dans `app/voice`, primitives `AppendGeneralCommentary` / `AppendInstructions` du sideband, repli **seulement sur refus du fournisseur**, jamais sur silence ni sur délai d'acquittement) et non un `Sideband.Announce` qui passerait à la stratégie suivante après un silence. Le détail livré est consigné dans `status.md`.
- **Route (D1)** : `POST /canvas/actions`, corps `{"action":"block_release","surface":"actions"}` (≤ 1 Kio, JSON objet, deux clés chaînes ; toute clé en plus → 400). Gardes dans l'ordre : `Host` (421), `Origin` présent (403), `Content-Type: application/json` (415), taille (413), JSON (400). Puis : action absente de l'ensemble des tags `action:*` des cartes connues ou surface qui ne la porte pas (422) ; aucune session ouverte (409 `{error:"no_session"}`) ; `Canvas.running > 0` ou action déjà en file (409 `{error:"busy"}`). Succès : **202** sans corps, le travail continue en arrière-plan (la file par session existante, profondeur 2). Jamais de détail d'erreur du fournisseur ni d'agent.
- **Session cible** : la session ouverte la plus récemment créée (le canevas est partagé ; une seule session voix à la fois en pratique). Publication du `plan`, de l'activité et de l'A2UI dans cette session. `delegation` n'est pas publié (pas de délégation GPT-Live) ; le `plan` porte `delegation` = identifiant d'opération interne `act-<n>` (chaîne), jamais confondu avec un `delegation.id` du fournisseur.
- **Plan d'action (D4)** : `selected` = les agents dont les tags contiennent `action:<nom>` (en pratique Livraison), `idle` = les autres ; sélection vide → 422 avant tout message. Le message A2A porte `metadata["genesis/action"] = {"name": <nom>, "surface": <id>}` + `genesis/activeSurfaces` ; le texte est vide. Aucun champ du client (contexte de l'événement, données de surface) n'est relayé.
- **Agent Livraison (D3)** : action `block_release` → un `updateDataModel` `{surfaceId:"checklist", path:"/checklist/decisionStatus", value:"Bloquée"}` ; `validate_release` → `"Validée"` (libellés de `dataset.json`). Résumé factuel, dit à la voix après `completed` : « La release 3.4 est bloquée. » / « La release 3.4 est validée. » (formulé depuis le libellé du jeu de données ; le résumé ne cite ni chiffre ni recommandation, que l'agent sans état ne connaît pas).
- **Acte 2 (D2)** : Livraison, vue plateforme (Android ou iOS), si `actions` ∉ `ActiveSurfaces` : ajoute à la mutation de la checklist `createSurface(actions)` → `updateComponents` (`ActionBar` plat, `data:{path:"/actions"}`) → `updateDataModel("/actions", {title:"Décision", actions:[{id:"block_release",label:"Bloquer la release",tone:"danger"},{id:"validate_release",label:"Valider la release",tone:"neutral"}]})`. Vue globale (acte 1) : pas de barre. `kit.SurfaceMessages` fournit déjà la création conditionnelle.
- **A2UI** : la liste blanche `A2UI_COMPONENTS` du compose passe à 5 ; propriétés admises `id`, `component`, `data` ; l'orchestrateur n'accepte `updateDataModel` que sur une surface active du même agent (déjà vérifié) — les sous-chemins sont déjà des JSON Pointers valides (Go et Dart).
- **Voix (D5)** : `Sideband.Announce(ctx, text)` : (1) `session.commentary.append` rattaché à la dernière `delegation.id` de la session (mémorisée par `app/voice`), attente de l'acquittement ; (2) si erreur d'acquittement : `session.instructions.append` avec une consigne de dire le texte tel quel ; après chaque envoi accepté, attente bornée (`VOICE_ANNOUNCE_TIMEOUT`, 4 s) d'un `EventOutputTranscriptDelta` ; aucun : stratégie suivante ; aucune : `slog` + `nil` (pas d'erreur fatale). Une seule annonce par action, jamais après `Close`.
- **App, clic (D6)** : `ActionBar` appelle `itemContext.dispatchEvent(UserActionEvent(name: id, sourceComponentId, context: {}))` ; `Surface` le propose à un `ActionDelegate` fourni par `CanvasBoard` qui envoie `ActionRequested(name, surfaceId)` au `CanvasActionBloc` (retour `true` : géré, rien n'est renvoyé à un LLM, aucun `Conversation`). **Risque** : si l'API `actionDelegate` n'existe pas telle quelle en 0.10.4, repli = écoute de `SurfaceController.onSubmit` dans `features/canvas` (voir T15). `CanvasActionBloc` : `droppable()` ; états `Idle`, `Sending(name)`, `Failed(reason)` ; `ActionBar` lit l'état pour désactiver les boutons (état passé par le conteneur, pas de `getIt` dans le widget).
- **Rejeu** : `A2uiGate.replayEvents` rejoue `raw` ; l'asset `act3-replay.jsonl` = actes 1 et 2 + `act2-actions` + `act3-block`, artefact dérivé relu par un test.
