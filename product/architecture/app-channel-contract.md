# Contrat v1 de l'app-channel (fonctionnalités 003, 004, 006, 007, 008, 009, 011 et côté client 005)

**En bref.** Ce que le backend expose réellement à l'app : routes HTTP et WSS `GET /app`, enveloppe `{v:1, type, session, t_ms, data}` et 9 types de messages. 003 (2026-10-29) a livré la voix (`orb.level`, `transcript`, `session.state`, `usage`) ; 004 (2026-10-29, vérifié en réel) ajoute l'A2UI relayé, l'activité des agents et la délégation ; 006 (J3-A, 2026-10-30, vérifiée en réel) ajoute le message `plan` (choix des agents, [pdr-0013](../decisions/pdr-0013-orchestrator-visible-agent-selection.md)), l'état `rejected` et le catalogue fermé `genesis` ; 007 (J3-B, 2026-10-30) ajoute la route `POST /canvas/reset` et décrit le côté client du catalogue `genesis` ; 008 (J4, 2026-10-30) rend le canevas **partagé entre les sessions voix** ([pdr-0058](../decisions/pdr-0058-backend-canvas-registry-survives-voice-sessions.md)) et fait muter les surfaces par `updateDataModel` seul ([pdr-0064](../decisions/pdr-0064-008-act2-transform-details-assistant-decided.md)) ; 009 (J5, 2026-10-30) ajoute la route `POST /canvas/actions` (clic), la cinquième surface `actions` et les sous-chemins inscriptibles ([pdr-0065](../decisions/pdr-0065-009-act3-interact-details-assistant-decided.md)) ; 011 (2026-10-30) ajoute le type `voice.interrupted`, émet enfin `canceled` et fixe les métadonnées A2A `genesis/intent`, `genesis/focus`, `genesis/scopeReason` ([p-ar-voice-interruption](voice-interruption.md)) ; 014 (2026-10-31) ajoute à `voice.interrupted` le champ facultatif `cause` (`stop` \| `correction`), sans nouveau type de message ([pdr-0076](../decisions/pdr-0076-014-silence-mic-correction-assistant-decided.md) D4). Ancrage : [pdr-0045](../decisions/pdr-0045-app-backend-channel-wss-recommended.md), [pdr-0051](../decisions/pdr-0051-orb-level-from-sideband-rms-recommended.md), [pdr-0052](../decisions/pdr-0052-one-gpt-live-session-per-act-recommended.md), [pdr-0036](../decisions/pdr-0036-real-a2a-agents-produce-a2ui.md). Contexte et séquences : [p-ar-agents-protocols](agents-protocols.md).

## Routes

| Route | Rôle | Réponses |
|---|---|---|
| `POST /voice/sessions` | corps `application/sdp` (offre) → answer SDP + en-tête `X-Session-Id` | 200 ; 400 corps vide ou illisible ; 413 trop gros ; 415 pas `application/sdp` ; 429 + `Retry-After` ; 502 `{error}` opaque |
| `DELETE /voice/sessions/{id}` | fermeture propre ([rt-graceful-close]) | 204 ; 404 inconnue ; 504 fermeture non confirmée à temps ; 502 sinon |
| `POST /canvas/reset` (007) | corps JSON `{}` : remet à vide le canevas partagé (§ Remise à vide) | 204 ; 400 corps illisible ou qui n'est pas un objet JSON ; 403 en-tête `Origin` présent ; 409 `{error}` opaque (délégation en file ou en cours, toutes sessions) ; 413 corps > 1 Kio ; 415 sans `Content-Type: application/json` ; 405 autres méthodes |
| `POST /canvas/actions` (009) | corps JSON `{"action":"<nom>","surface":"<id>"}` : clic sur la Barre d'actions (§ Action) | 202 sans corps ; 400 corps illisible ou non strict ; 403 `Origin` présent ; 409 `{error:"no_session"}` ou `{error:"busy"}` ; 413 > 1 Kio ; 415 sans `application/json` ; 422 action inconnue ou surface qui ne la porte pas ; 500 opaque |
| `GET /healthz` | sonde du conteneur | 200 `ok` |
| `GET /app` (WSS) | toutes les sessions, y compris futures ; `?session=<id>` = filtre facultatif | 400 identifiant invalide ; 404 identifiant inconnu ; 1008 abonné trop lent |

Toutes les routes : 421 `{error}` si l'en-tête `Host` n'est pas autorisé (anti DNS rebinding). Identifiant de session : `[A-Za-z0-9_-]{1,128}`. Erreurs en JSON `{error}`, jamais de détail du fournisseur ni de clé.

## Enveloppe et types de messages

`{v:1, type, session, t_ms, data}` ; `session` = id de la session voix ; `t_ms` en ms (temps du fournisseur pour les transcripts). **004** ajoute deux champs facultatifs au premier niveau, omis si vides : `agent` (nom de la carte de l'agent émetteur) et `task` (id de tâche A2A). Les messages `a2ui` les portent toujours ; `agent.activity` les répète depuis `data`. `agent` vaut `"orchestrateur"` pour une **compensation** `deleteSurface`. Le journal a les mêmes champs.

| `type` | `data` | Cadence / note |
|---|---|---|
| `orb.level` | `{level}` 0..1 | 5 Hz, RMS PCM16 24 kHz par blocs de 200 ms ([rt-gpt-live-output-level]) |
| `transcript` | `{role: user\|ai, text, start_ms, end_ms}` | pas de `final` : GPT-Live n'émet pas de fin de tour ([rt-gpt-live-lifecycle]) ; FR-19 |
| `session.state` | `{state, reason?}` | `connecting` (avant l'answer), `active` (sideband attaché), `closed` |
| `usage` | `{seconds, context_ratio}` | issu de `usage.updated` ([rt-gpt-live-sideband]) |
| `delegation` (004) | `{id, offset_ms}` | publié à la création d'une délégation par le modèle, avant tout `agent.activity` ; rend NFR-02 mesurable (`offset_ms` = temps du fournisseur) |
| `plan` (006) | `{delegation, selected[], idle[]}` | noms d'agent (tableaux, jamais `null`) ; pour une action (009), `delegation` = identifiant d'opération interne `act-<n>` (jamais un `delegation.id` du fournisseur), `selected` = Livraison seul ; publié **avant toute activité** de la délégation ; journalisé, **rejoué aux abonnés tardifs** (rétention du hub) ; un `deleteSurface` ne l'efface pas ; un agent de `idle` ne reçoit aucun `agent.activity` ; `selected` vide = demande hors catalogue (RG-08) |
| `agent.activity` (004) | `{agent, task, state, label?, detail?}` | `state` ∈ `working`, `completed`, `failed`, `rejected` (006) ; `canceled` **émis depuis 011** (« Stop », sans `detail`) ; `label` = nom du premier skill de la carte (FR-03) |
| `a2ui` (004) | le **message A2UI v0.9 lui-même**, relayé tel quel et sans enrobage ([genui-a2ui-messages]) | une opération par message : `createSurface`, `updateComponents`, `updateDataModel`, `deleteSurface` ; `theme` de `createSurface` relayé, ignoré par l'app |
| `voice.interrupted` (011) | `{at_ms, cause?}` | publié quand un mot d'arrêt est confirmé, ou (014) quand une correction en vol est confirmée et qu'une demande antérieure est en vol ou en file ([p-ar-voice-interruption](voice-interruption.md)) ; `at_ms` = `start_ms` du delta déclencheur ; **`cause` (014, facultatif, fermé) ∈ {`stop`, `correction`}** : absent = `stop`, valeur inconnue traitée comme `stop` côté app, **le payload d'un Stop reste `{"at_ms":N}`** ; avec `correction`, l'app termine l'interruption à la première délégation d'offset ≥ `at_ms` ; **jamais rejoué** (comme `orb.level`), gardé dans le journal JSONL ; l'app coupe la piste distante, l'orbe passe « Interrompue ». Faire taire et micro coupé n'ont **aucun message** (§ Côté client) |

- **`detail`** d'un `failed` : ensemble fermé « injoignable », « délai dépassé », « A2UI invalide », « échec de l'agent », « session fermée » ; jamais d'erreur brute ni d'URL. Un `rejected` (006) porte le détail fermé « hors périmètre ».
- **Tout agent de `plan.selected` reçoit un `agent.activity` terminal** (`completed`, `failed`, `rejected` ou, depuis 011, `canceled`), y compris un délai dépassé avant le suivi de sa tâche : le rail (FR-03, 007) n'a pas d'agent « bloqué en cours ».
- **`working`** est publié à la réception de l'état A2A `submitted` ; `task` reste stable jusqu'à l'état terminal ([proto-a2a-task-lifecycle]). Carte injoignable : `agent` = dernier nom connu, sinon l'hôte de l'URL.
- **Raisons de `closed`** : du fournisseur, `close_requested`, `expired`, `remote_hangup`, `content` ; du backend, `connection_lost`, `max_session` (`VOICE_MAX_SESSION`, Q-68), `attach_failed`.

## Ordre, backlog, rétention, journal

- **Ordre garanti** : par agent, les messages `a2ui` sont publiés dans l'ordre du flux A2A ; l'ordre `delegation` → `agent.activity working` → `a2ui` est vérifié (acceptation B1). Le registre de surfaces est partagé (§ Portée) ; la publication d'une session se fait sous le verrou de cette session.
- **Backlog** : à la connexion, rejeu des derniers messages (hors `orb.level` et `voice.interrupted`), 50 au plus, dans l'ordre global de publication, sans doublon avec le direct ; une session est oubliée une fois `closed` publié.
- **Rétention du hub (004)** : en plus, **512 messages `a2ui` et `agent.activity` par session** (option injectée ; **limite 008** : elle reste par session, une session fermée n'est plus rejouée à la suivante, et le registre backend est la source de vérité) que les transcripts n'évincent pas, rejoués avec le backlog. Éviction : d'abord les `agent.activity`, puis les mises à jour, **jamais le `createSurface` d'une surface vivante** (dernier recours théorique seulement, inatteignable avec 6 surfaces). Un `deleteSurface` fait oublier tous les messages de la surface et n'est pas retenu.
- **Journal** : `<JOURNAL_DIR>/<session>.jsonl`, une ligne = enveloppe sans `v` + `unix_ms`, mêmes noms de champs ; base du journal horodaté ([p-ar-replay](replay.md)).
- **Portée (008)** : le registre de surfaces est **unique, côté backend, partagé par toutes les sessions voix** (`orchestrate.Canvas` : registre, compteur `running`, verrou `mu`) et survit à la fermeture d'une session ([pdr-0058](../decisions/pdr-0058-backend-canvas-registry-survives-voice-sessions.md), Q-70 et Q-73). La session ne porte que la conversation ; `Pipeline.Close` ne vide plus le registre. Depuis 006, `ContextID` A2A = id de session : le registre de l'orchestrateur est la seule source de vérité (§ Surfaces actives). Ordre des verrous : `Canvas.mu → Manager.mu → session.mu → Pipeline.mu → Registry.mu → orphMu`.
- **Orphelins (008)** : la compensation (`deleteSurface`) d'une session fermée en pleine tâche retire les surfaces du registre sans que l'app la reçoive ; elle est gardée dans `Canvas.orphans` et publiée **à la session suivante** (auteur `orchestrateur`, avant le `plan`), ou fusionnée à la remise à vide.
- **Surfaces actives** (006) : à chaque requête, l'orchestrateur lit sous le verrou les surfaces actives de l'agent (`Registry.ActiveFor`) et les passe dans les `metadata` du message A2A, clé **`genesis/activeSurfaces`** (`[]any` de chaînes ; liste vide = clé présente). Le composeur de l'agent n'émet `createSurface` que pour une surface qu'il produit et qui manque à cette liste (bornes côté agent : ≤ 16 éléments, ≤ 64 runes). Effet : une surface déjà ouverte n'est jamais recréée ; elle ne se rouvre qu'après un `deleteSurface` (pdr-0058). **Métadonnées A2A de 011** : `genesis/focus` (requête, `{platform, compareTo}`), `genesis/intent` (état `completed`, validée sur la forme seulement) et `genesis/scopeReason` (état `rejected`, motif fermé journalisé en slog seulement, jamais sur le canal) : [p-ar-voice-interruption](voice-interruption.md). **Motifs de refus (012)** : `version`, `two_platforms`, `compare_without_platform`, `compare_unavailable` et **`view_unavailable`** (vue que le catalogue ne produit pas ; le client A2A le reconnaît, la voix dit la phrase `failure_rejected_view`, [p-ar-agents-protocols](agents-protocols.md)).

## Remise à vide du canevas : `POST /canvas/reset` (007, FR-11, RG-23)

Livrée pour que la remise à vide de l'app vide aussi le registre de surfaces du backend ([pdr-0058](../decisions/pdr-0058-backend-canvas-registry-survives-voice-sessions.md), [pdr-0063](../decisions/pdr-0063-007-stage-ui-details-assistant-decided.md) D4). Sans cela, une nouvelle demande ne recréerait aucune surface (le registre les croirait actives).

| Point | Contrat |
|---|---|
| Gardes (dans l'ordre) | `Host` (421, toutes routes) ; `Origin` présent → **403** (le client Flutter n'en envoie pas) ; `Content-Type: application/json` → sinon **415** ; corps ≤ **1 Kio** (`MaxBytesReader`, 413) ; corps illisible ou non objet JSON → **400** ; aucun en-tête CORS émis. Raisons : [p-ar-security](security.md) |
| Effet | registre partagé vidé **une seule fois**, puis un `deleteSurface` par surface active (orphelins fusionnés, sans doublon), **triés par `surfaceId`**, publiés par l'agent `orchestrateur` dans **chaque** session ouverte ; **aucun message s'il n'y a aucune session ouverte** (registre vidé quand même) ; **`ContextID` conservé** ; le hub oublie la rétention de chaque surface, le **journal garde tout** ; **idempotent** (registre vide : rien d'émis, 204) |
| Occupé (409) | refusé si `Canvas.running > 0` (exécution de `Run` en cours, étape `plan` comprise, **fermeture en cours comprise**) ou si une session ouverte a une délégation en file (`pending`, incrémenté avant la mise en file) ; réponse `{error}` opaque, rien n'est changé |
| Une seule passe | tout se fait sous `Canvas.mu` : un `Run` qui démarre pendant la passe attend (`enter`) et commence sur un canevas vide ; plus de course entre deux passes (008) |
| Autres erreurs | 500 `{error}` opaque (jamais de détail) |

Détail Go : [p-ar-backend](backend.md). Tests : acceptation G7 et tests du canevas partagé sous `-race` (remise à vide pendant une délégation → 409 ; sans session ouverte → registre vidé ; deux remises concurrentes → chaque surface supprimée une fois ; orphelins publiés à la session suivante).

## Action : `POST /canvas/actions` (009, FR-08, RG-18)

Transport du clic ([pdr-0065](../decisions/pdr-0065-009-act3-interact-details-assistant-decided.md) D1) : une requête HTTP avec accusé synchrone, plutôt qu'une écoute WSS montante (le hub est en diffusion seule). Détail Go : [p-ar-backend](backend.md).

| Point | Contrat |
|---|---|
| Gardes | celles de `/canvas/reset` (`Host` 421, `Origin` 403, `Content-Type` 415, ≤ 1 Kio 413, aucun CORS : [p-ar-security](security.md)), factorisées dans une garde commune |
| Corps strict | un objet JSON à **deux clés exactes**, `action` et `surface` (chaînes non vides, casse exacte) ; clé en trop, clé en double, octets après la valeur : 400 |
| Ordre des refus | regex du nom `^[a-z][a-z_]{0,39}$` (422) → aucune session ouverte (409 `no_session`) → validation (tag `action:<nom>` d'une carte lue ; surface active possédée par le même agent) → 422 → occupé (409 `busy`). Donc **sans session ouverte, une action de nom valide mais inconnue donne 409 et non 422** (la validation passe par la session cible) |
| Validation | **synchrone, sans réseau** : seules les cartes déjà lues (`LastTags`) et le registre sont consultés |
| Occupé | `busy` si `Canvas.running > 0`, si une session ouverte est occupée ou si une délégation vocale a pris la file ; **pendant une délégation, la route répond `busy` jusqu'à l'acquittement du commentaire vocal** (constaté en réel) ; l'app réessaie |
| Effet | travail détaché de `r.Context()` (202 renvoyé avant la fin) ; `Manager.Act` atomique sous `Canvas.mu` (ordre `Canvas.mu` → `m.mu` → `session.mu`) ; session cible = ouverture la plus récente ; `Delegation.Action` ; plan Livraison seul ; aucun message `delegation` publié |
| Message A2A | metadata `genesis/action` = `{name}` seul + `genesis/activeSurfaces` + **une part texte** (le nom ; `a2a-go` refuse un message sans part). Le corps du client (`surface` comprise) n'est jamais relayé à l'agent |
| Fin | l'agent répond par `updateDataModel` de `/checklist/decisionStatus` ; `agent.activity` terminal ; la voix confirme **après** `completed` (`VoiceReply.Announce`, [p-ar-agents-protocols](agents-protocols.md)) ; échec ou refus de l'agent : checklist inchangée, phrase d'échec dite, `failed` / `rejected` au rail |

## Politique d'échec (004, 006)

Relais **message par message** dès validation (RG-02, NFR-02), sans attendre la fin de la tâche. Au premier message invalide, à `failed`/`rejected`/`canceled`, à `AGENT_TIMEOUT` ou à un flux terminé sans état final :

1. arrêt de la lecture et `CancelTask` ;
2. **compensation** : un `deleteSurface` émis par l'orchestrateur pour chaque surface créée par la tâche (ordre inverse), sans réécrire de message d'agent ([pdr-0036](../decisions/pdr-0036-real-a2a-agents-produce-a2ui.md)) ;
3. `agent.activity failed` avec son `detail` ;
4. commentaire vocal d'échec honnête, sans chiffre ; **jamais de silence** (phrase neutre, ou phrase propre au rejet de l'agent ; une tâche `completed` sans résumé reçoit aussi sa phrase), jamais après la fermeture de session. Le résumé de l'agent n'est dit que si la tâche est `completed` ET tous les messages valides ([ma-real-tool-results]).

Décision : les surfaces d'un agent qui échoue après affichage partiel sont retirées (cohérent avec FR-16/RG-14), non laissées en état neutre (RG-10) — Q-69 tranchée → [pdr-0056](../decisions/pdr-0056-failed-agent-partial-surfaces-removed.md). Livré en 006 pour `failed`.

**Refus (006)** : un agent **retenu** qui refuse (`AgentRejected`) passe en `agent.activity rejected` (détail « hors périmètre »), pas en `failed` : **pas de commentaire d'échec ni de mention vocale** du refus, et en pratique rien à compenser (les agents refusent avant tout message A2UI) ; cas limite, **réel depuis 012** (refus `view_unavailable` du modèle après le squelette anticipé) : les surfaces émises sont retirées par l'orchestrateur (`deleteSurface`, comme pour `failed`, pdr-0056 ; [Q-82](../roadmap/open-questions.md)). Un refus partiel n'est pas un échec du plan ; si **tous** les agents retenus refusent, la voix dit `failure_rejected` (avec alternative, RG-08), ou `failure_rejected_view` quand le motif est `view_unavailable`. Aucun agent retenu (`plan.selected` vide) : aucun appel, la voix dit `out_of_catalog`. Échec partiel (au moins un `failed`, d'autres `completed`) : le résultat des agents qui ont réussi est dit, suivi de `partial_failure` qui nomme l'agent en échec (RG-04, [ma-real-tool-results]).

## File par session

Une file et une seule goroutine de traitement par session, profondeur 2 : une délégation reçue pendant une autre est mise en file et reçoit aussitôt son commentaire générique ; au-delà, commentaire honnête sans appel d'agent. Un `delegation.id` déjà vu (ou vide) est ignoré. Les agents d'un plan tournent en parallèle. **011** : la demande est prise dans `session.run` après `REQUEST_WINDOW_SETTLE` (jamais d'attente dans `Delegate`), et `Interrupt` vide la file et annule l'exécution en cours sans fermer la session. Depuis 006, **l'orchestrateur choisit les agents** ([pdr-0013](../decisions/pdr-0013-orchestrator-visible-agent-selection.md)) : il lit chaque carte une fois par délégation, puis un `Planner` (`TagPlanner` : tags des skills, mots entiers, remplaçable par un LLM, Q-17) retient un sous-ensemble ; détail dans [p-ar-backend](backend.md).

## Validateur A2UI v0.9 (côté orchestrateur)

Les agents produisent l'A2UI ; l'orchestrateur la **valide et la relaie** ([pdr-0036](../decisions/pdr-0036-real-a2a-agents-produce-a2ui.md), [genui-a2ui-security]). La map reçue n'est jamais modifiée.

| Niveau | Règles |
|---|---|
| Message (sans état) | ≤ 64 Kio, profondeur JSON ≤ 16 ; `version == "v0.9"` ; une seule opération et aucune autre clé de premier niveau ; `surfaceId` `^[A-Za-z0-9_-]{1,64}$` |
| `createSurface` | `catalogId` = `A2UI_CATALOG_ID` ; `sendDataModel` booléen |
| `updateComponents` | 1 à 100 composants, `id` uniques dans le message ; `component` dans la liste blanche `A2UI_COMPONENTS` ; `child`/`children` en identifiants ou gabarit `{componentId,path}` ; **propriétés (006)** : si `A2UI_ALLOWED_PROPS` est renseignée, toute autre clé est refusée (`bad_property`, message fixe sans valeur) ; si `A2UI_BINDING_PROPS` est renseignée, chaque propriété listée doit valoir `{path: <JSON Pointer ≤ 128 runes>}` (jamais un littéral). Listes vides : aucun contrôle (J2 intact) |
| `updateDataModel` | `path` JSON Pointer ; **009** : seul `/<surface>` ou un sous-chemin déclaré par `A2UI_WRITABLE_SUBPATHS` (`chemin:type`, séparés par des virgules ; compose : `/checklist/decisionStatus:string`) est accepté, avec une valeur du bon type, sinon `path_not_allowed` (chemin vide ou `/`, autre sous-chemin, sous-chemin d'une autre surface, mauvais type). Un pointeur mal formé reste `bad_pointer`. ⚠️ **Réserve** : sans cette variable le validateur Go ne contrôle aucun chemin ; le compose la pose et `check-compose.sh` la compare à `catalog.json` |
| Session (registre) | `createSurface` refusé si la surface existe ou si **6 surfaces** sont ouvertes ([pdr-0019](../decisions/pdr-0019-six-limit-applies-to-surfaces.md)) ; toute autre opération exige une surface active **du même agent** (identifiant d'agent, pas son nom affiché) ; ≤ 200 composants par surface, ≤ 64 messages par tâche |
| Fin de tâche | chaque surface créée a un `root` et toutes ses références sont résolues, sinon échec (le rendu progressif est valide en v0.9) |

Codes d'erreur fermés, jamais exposés à l'app ni à la voix. `NewValidator` refuse une configuration où `A2UI_BINDING_PROPS` contient une propriété absente de `A2UI_ALLOWED_PROPS`. Les entrées de l'orchestrateur sont bornées : tags de carte (≤ 32, de 1 à 40 runes, sans caractère de contrôle), noms d'agent nettoyés (40 runes, contrôles et bidi retirés), doublons de `AGENTS` refusés. Validation côté client : livrée en 007, voir § Côté client (Q-71 → [pdr-0053](../decisions/pdr-0053-client-side-a2ui-validation-from-007.md)).

## Côté client (005 et 007, 2026-10-30)

Implémenté dans `shared/backend_channel`, `features/voice_session`, `entities/catalog` et `features/canvas` ([p-ar-frontend](frontend.md), [p-ar-frontend-screen](frontend-screen.md)).

| Point | Comportement |
|---|---|

| Messages illisibles | type inconnu ou enveloppe illisible : **ignoré et consigné** (phrases fermées, jamais le contenu), jamais fatal ; un message A2UI refusé par le décodeur est écarté de la même façon |
| Perte du canal | événement `ChannelLost` (le flux d'événements n'émet jamais d'erreur) ; `closed` du backend de la session courante : libération locale sans `DELETE` ; perte du WSS : `DELETE` au mieux puis libération (pas de session facturée sans visuels) |
| Journal local | `EnvelopeLog` (`GENESIS_APP_LOG`, inactif sans chemin) : format du journal backend (enveloppe sans `v`, mêmes noms de champs) + `unix_ms` lu sur l'**horloge de l'app** à la réception ([pdr-0038](../decisions/pdr-0038-latency-measured-on-app-clock.md)), jamais le `t_ms` du backend ; **base du rejeu (J6)** |
