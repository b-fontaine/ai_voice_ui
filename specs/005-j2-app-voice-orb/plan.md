## Contrats
- **Canal et relais** : [p-ar-app-channel-contract] (routes, enveloppe, types, raisons de `closed`, détails d'échec). Le client ne suppose rien hors contrat ; un type inconnu ou une enveloppe illisible est ignoré (compteur, journal), jamais fatal. `?session=` non utilisé (une seule session à la fois).
- **Session voix** ([rt-flutter-webrtc-gpt-live-connect], [rt-gpt-live-webrtc-session]) : `getUserMedia` avec `echoCancellation`, `noiseSuppression`, `autoGainControl` ; piste ajoutée, `createDataChannel('oai-events')` avant `createOffer` ; `setLocalDescription` puis attente de `RTCIceGatheringStateComplete` (10 s) ; envoi de `localDescription.sdp` ; pas de `audio.format`, pas de `session.start` ; réponse appliquée en `answer`. Fermeture : `DELETE` (borné), puis `track.stop()`, flux `dispose()`, canal `close()`, `pc.close()` ; chaque étape tolère l'erreur de la précédente. Le data channel n'est **pas** utilisé par l'app (les événements passent par le backend) mais reste ouvert, requis par la session.
- **Une seule capture micro** : `getUserMedia` uniquement ; ni `record` ni second flux ([proj-avw-risks] n°3).
- **Orbe** ([perf-audio-visualizer-60hz], pdr-0051) : `OrbLevelController` reçoit `OrbLevelChanged` (5 Hz), expose `ValueListenable<double>` mis à jour par un `Ticker` (montée rapide, descente plus lente, constantes injectées) ; un `CustomPainter(repaint: level)` sous `RepaintBoundary` ; aucun niveau dans un state Bloc. Seuil de « parole » et constantes de lissage = paramètres du widget, valeurs par défaut dans `app/config`.
- **Blocs** (Bloc uniquement, events/states `sealed`, transformer explicite) : `VoiceSessionBloc` — `VoiceSessionStarted` (`restartable`), `VoiceSessionStopped` (`droppable`), `VoiceEventReceived` (`sequential`) ; states `Idle`, `Connecting`, `Active`, `Failed(reason)`, `Stopping`. `TranscriptBloc` (`sequential`), `AgentActivityBloc` (`sequential`). Les flux entrent par événement de souscription et `emit.onEach` ([bloc-emit-foreach]).
- **DI** ([di-setup-versions], [di-no-service-locator], pdr-0044) : `@InjectableInit` dans `app/di`, un module d'enregistrement par paquet **écrit dans `app/di`** (pas de générateur dans chaque paquet pour la démo ; réexamen si l'architecte le demande), environnements `live` (WSS + relais HTTP + WebRTC réels) et `test` (fakes aux frontières). Injection par constructeur partout ; `getIt` n'est appelé que dans `app/di` et `pages/genesis_canvas`. Portée get_it par session : la session voix, le journal et les Blocs sont des fabriques, recréées à chaque « Démarrer ».
- **Configuration** : `GENESIS_BACKEND_URL`, `GENESIS_APP_LOG`, `GENESIS_SCENARIO`, `GENESIS_SNAPSHOT` ; **aucune** variable de clé. L'URL WSS se déduit de l'URL HTTP (`ws`/`wss`).
- **Horloge** : `AppClock` injectable ; `SessionEventLog` y lit `unix_ms` à la réception (pdr-0038), jamais le `t_ms` du backend.

## Risques
- `flutter_webrtc` sous Linux n'est exercé qu'en réel (les tests passent par un `VoiceTransport` factice) → essai réel unique en Vérification, compilation du plugin couverte par `gate.sh --full` et `app-smoke.sh`.
- Conflits de résolution entre `injectable_generator` / `build_runner` / `analyzer` et `bdd_widget_test` (déjà rencontré avec `bloc_test`, note KB) → figer d'abord les versions dans une tâche dédiée (T01) et la valider par `flutter pub get` + `gate.sh --unit flutter` avant toute autre.
- Niveau d'orbe à 5 Hz qui paraît saccadé → interpolation au `Ticker` ; hypothèse « 5 Hz suffisent » à vérifier à l'œil lors de l'essai réel (pdr-0051 prévoit le réexamen).
- Fuite de micro ou de connexion à l'arrêt → V3 vérifie l'ordre de fermeture et la redémarrabilité ; `dispose` de la page appelle `stop`.
- Capture sous Xvfb sans micro : `getUserMedia` échoue → l'erreur est une nature fermée de `Failed`, pas un plantage (V4).
