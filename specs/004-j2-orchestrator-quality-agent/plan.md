## Contrats
- **Délégation `client`** ([rt-gpt-live-delegation]) : `session.delegation.created` (`delegation.id`, sans les mots de l'utilisateur) → la demande est reconstruite depuis `session.input_transcript.delta` reçus depuis la délégation précédente ; retour par `session.commentary.append` (dit, paraphrasable, ≤ 500 tokens, `event_id` unique, acquitté par `…appended`) ; le commentaire générique part sans attendre l'agent (RG-04) et annule l'accusé automatique ; jamais de faux résultat ([ma-real-tool-results]).
- **A2A** ([proto-a2a-agent-card], [proto-a2a-go-v03-compat]) : l'orchestrateur est client natif v1.0 de l'agent ; l'agent publie sa carte (`/.well-known/agent-card.json`, skill `quality-kpi`) ; flux : tâche `submitted`, `status-update` dont les `parts` `data` portent chacune UN message A2UI v0.9, puis un `Artifact` texte (résumé factuel) et `completed`. Uniquement `map[string]any` et `[]any` dans les parts (piège gob).
- **App-channel** (extension du contrat v1 de 003) : types `a2ui` (`data` = message A2UI v0.9 tel que validé, envoyé sans recomposition) et `agent.activity` (`state`: `working`, `completed`, `failed`) ; mêmes enveloppe, `session`, backlog (rejoués à la connexion : `a2ui` et `agent.activity`, pour qu'une app qui se connecte tard retrouve l'état) et journal.
- **Validateur A2UI v0.9** ([genui-a2ui-security], [genui-a2ui-messages]) : une et une seule opération par message (`createSurface`, `updateComponents`, `updateDataModel`, `deleteSurface`), `version == "v0.9"`, `surfaceId` non vide ; `createSurface.catalogId` égal au `A2UI_CATALOG_ID` configuré ; composants à `id` uniques avec un `root` ; références d'enfants résolues ; au plus 6 surfaces ouvertes (pdr-0019) ; taille bornée.
- **Signatures imposées par les tests d'acceptation (T01-T03, B4)** :
  - `port.EventDelegationCreated` (type d'événement) et `port.LiveEvent.DelegationID string` ; `port.Sideband` gagne `AppendCommentary(ctx context.Context, delegationID, text string) error` et `AppendThinking(ctx context.Context, delegationID, text string) error` ; `port.RemoteAgent` (carte + `SendStreamingMessage`, interne : non imposé par les tests, qui passent par `AGENTS`).
  - `domain` : `TypeA2UI = "a2ui"` avec `A2UI{Message map[string]any}` (sérialisé tel quel dans `data`) ; `TypeAgentActivity = "agent.activity"` avec `AgentActivity{Agent, Task, State, Detail string}` (JSON `agent`, `task`, `state`, `detail`) ; états `ActivityWorking = "working"`, `ActivityCompleted = "completed"`, `ActivityFailed = "failed"`.
  - `port` (T10, `backend/orchestrator/internal/port/agent.go`) : `RemoteAgent{Card(ctx) (AgentCard, error); Send(ctx, AgentRequest) (<-chan AgentUpdate, error)}` ; `AgentCard{Name, Description string; Skills []string}` ; `AgentRequest{Text, ContextID string}` ; `AgentUpdate{Kind AgentUpdateKind; A2UI map[string]any; Text string; Err error}` avec `Kind` ∈ {`UpdateA2UI`, `UpdateText`, `UpdateCompleted`, `UpdateFailed`} ; canal fermé après `UpdateCompleted` ou `UpdateFailed`.
  - Configuration lue par `bootstrap.ConfigFromEnv` : `AGENTS` (URL de cartes, séparées par des virgules), `A2UI_CATALOG_ID`, `AGENT_TIMEOUT` (durée) ; `bootstrap.New` ne contacte pas les agents (la carte est lue à la délégation, sinon une carte injoignable ferait échouer le démarrage).
  - Agent `agent` : `agent.Config{PublicURL, CatalogID, DatasetPath string}` et `agent.NewServer(cfg agent.Config) (http.Handler, error)` dans `backend/agents/quality/internal/agent` ; le handler sert la carte (`/.well-known/agent-card.json`) et le JSON-RPC natif v1.0 sur `POST /`.
  - Comportement : le nom de l'agent de `agent.activity` est le `name` de la carte ; commentaire générique d'abord (sans chiffre), puis un commentaire fondé sur le résumé texte de l'artefact (« 99,57 % ») ou, en cas d'échec (tâche `failed`, carte injoignable, A2UI invalide), un commentaire sans « % » qui contient « échec », « pas pu », « impossible », « indisponible » ou « erreur ».
- **Configuration** : `AGENTS` (liste d'URL de carte, séparées par des virgules), `A2UI_CATALOG_ID`, `AGENT_TIMEOUT` ; l'agent : `AGENT_LISTEN_ADDR`, `DATASET_PATH` facultatif (jeu embarqué par défaut).
- **Jeu de données** ([p-fn-dataset], pdr-0040) : sessions sans crash global 7 j = 99,57 % (seuil ≥ 99,50 %, « à risque ») ; copie JSON figée et versionnée sous `backend/agents/quality/dataset/`, identique en valeur à `product/functional/dataset.md`.

## Amendements de la revue du plan (A1-A13)

**A1 — Branchement voix → orchestrateur et cycle de vie.** `voice.Service` reste le seul consommateur de `sb.Events()` et le seul propriétaire des `delegation.id`. Il reçoit par constructeur un port `port.Delegations` : `Open(sessionID string, start time.Time, reply port.VoiceReply) port.SessionDelegations`, avec `SessionDelegations{Transcript(port.LiveEvent); Delegate(id string, offsetMs int64); Close(ctx)}` ; `VoiceReply` = sous-ensemble `AppendCommentary` du sideband ; implémenté par `app/orchestrate` (aucune slice applicative n'en importe une autre). `Transcript` et `Delegate` ne bloquent jamais `supervise` (file bornée, `select default` journalisé). Sur tous les chemins de fin (EventClosed, coupure, abandon, plafond, Shutdown), `supervise` appelle `Close` AVANT de publier `session.state closed` : (1) `agent.activity{failed, detail:"session fermée"}` pour chaque tâche en vol ; (2) annulation des contextes, `CancelTask` sur un contexte neuf borné à 1 s ; (3) attente des goroutines ≤ `GuardTimeout` ; (4) plus aucun `Publish` ni `Append*` ensuite (drapeau sous le verrou de publication de la session, pour ne pas recréer d'entrée dans le hub). `App.Close` attend la fin des délégations avant de fermer le hub puis le journal.

**A2 — Délégations qui se recouvrent.** Une file par session, une seule goroutine de traitement ; une délégation reçue pendant une autre est mise en file (profondeur 2) et reçoit aussitôt son commentaire générique ; au-delà : commentaire honnête (« je termine d'abord la demande en cours »), sans appel d'agent. Dans une délégation, les agents du plan tournent en parallèle ; registre de surfaces et `Publish` sous un même verrou de session (ordre garanti par agent, décompte des 6 surfaces atomique). Un `delegation.id` déjà vu est ignoré (ensemble borné). J2 : le plan envoie la demande à tous les agents configurés (un seul) ; sélection par skills en J3 ; révision en J4 ; annulation `stop` en J7.

**A3 — Validateur A2UI v0.9.** *Sans état, message par message* : taille sérialisée ≤ 64 Kio, profondeur JSON ≤ 16 ; `version == "v0.9"`, une seule opération et aucune autre clé de premier niveau ; `surfaceId` `^[A-Za-z0-9_-]{1,64}$` ; `createSurface` : `catalogId == A2UI_CATALOG_ID`, `sendDataModel` booléen ; `updateComponents` : 1 à 100 composants, `id` uniques dans le message, `component` dans la liste blanche injectée `A2UI_COMPONENTS` (J2 : `Column,Text`), `child`/`children` en identifiants ou en gabarit `{componentId,path}` ; `updateDataModel` : `path` vide ou JSON Pointer. *Avec état (registre par session)* : `createSurface` refusé si la surface est active ou si 6 surfaces sont déjà actives (pdr-0019) ; toute autre opération exige une surface active **du même agent** ; ≤ 200 composants cumulés par surface, ≤ 64 messages par tâche ; en fin de tâche, chaque surface créée doit avoir un `root` et toutes ses références résolues, sinon la tâche échoue (le rendu progressif — enfants envoyés plus tard — est valide en v0.9). Le validateur ne modifie jamais la map reçue.

**A4 — Rétention du hub.** Le hub tient, par session, une rétention séparée pour `a2ui` et `agent.activity` (512 messages au plus, option injectée) que les transcripts n'évincent pas ; un `deleteSurface` fait oublier les messages de la surface ; au rejeu, fusion par ordre de publication avec le backlog ordinaire. Sans cela `hubBacklog = 50` perd `createSurface` après quelques phrases.

**A5 — Flux partiel, délai, échec.** Relayer chaque message dès qu'il est validé (pas de validation de tout le lot : RG-02, NFR-02). Au premier message invalide, à `failed`/`rejected`/`canceled`, à `AGENT_TIMEOUT` ou à un flux terminé sans état final : (1) arrêter la lecture et annuler (`CancelTask`) ; (2) publier un `deleteSurface` émis par l'orchestrateur pour chaque surface créée par cette tâche (ordre inverse) ; (3) `agent.activity failed` ; (4) commentaire d'échec. Le résumé de l'artefact n'est utilisé que si l'état est `completed` ET tous les messages valides. ⚠️ Arbitrage visible sur scène (retirer la surface partielle vs la laisser en « état neutre », RG-10) : comportement provisoire = retirer, cohérent avec FR-16 ; Q-69 posée au porteur à la clôture.

**A6 — Délai et agents absents.** `AGENT_TIMEOUT` borne toute la tâche (carte + flux), obligatoire et > 0 si `AGENTS` est non vide, défaut fixé dans le compose : 8 s (NFR-03). `AGENTS` vide : l'orchestrateur démarre ; une délégation reçoit un commentaire « aucun agent disponible », sans `agent.activity`.

**A7 — Contrat `agent.activity` / `a2ui` pour 005.** `working` est publié **à la réception de `submitted`**, `task` = identifiant de tâche A2A stable jusqu'à l'état terminal ; `agent.activity` gagne `label` (nom du skill de la carte, FR-03) ; `detail` ∈ ensemble fermé {« injoignable », « délai dépassé », « A2UI invalide », « échec de l'agent », « session fermée »}, jamais d'erreur brute ; état `canceled` ajouté (J7) ; carte injoignable : `agent` = dernier nom connu sinon hôte de l'URL. L'enveloppe `a2ui` gagne `agent` et `task` en premier niveau (`agent: "orchestrateur"` pour une compensation) ; `data` reste le message brut. `theme` de `createSurface` : relayé, ignoré par l'app.

**A8 — Commentaires vocaux.** *Adaptateur `openailive`* : `event_id` = `gc-<delegationID>-<n>` (compteur atomique) ; `run` route `session.commentary.appended`, `session.thinking.appended` et `error` vers une table d'attente indexée par `client_event_id` ; `AppendCommentary` attend l'acquittement ≤ `VOICE_APPEND_ACK_TIMEOUT` (défaut 2 s) puis erreur, jamais de nouvelle tentative (sinon phrase dite deux fois) ; échec immédiat après la fin de la boucle ; rejet au-delà de 1 000 runes ; supprimer `errNotImplemented`/`TestAppendNotYetImplemented`. `AppendThinking` n'a aucun usage défini en J2 : retiré du port. *Orchestrate* : le générique part dès `Delegate`, dans une goroutine, avant la lecture de la carte ; le final attend la fin du générique (ordre garanti) ; le final = gabarit sans chiffre + résumé de l'artefact cité comme donnée (coupé à 600 runes, caractères de contrôle retirés) ; l'échec = gabarit sans chiffre ; toutes les phrases sont injectées par fichier de configuration (pdr-0009), jamais en dur ; `VOICE_ACK_DELAY_MS` (`delegation.acknowledgement_delay_ms`) pour éviter deux phrases de remplissage.

**A9 — Reconstruction de la demande.** `LiveEvent` gagne `OffsetMs` (`offset_ms`, `start_ms`, `end_ms` partagent la « Live session timeline » d'après les commentaires du SDK). Demande = concaténation telle quelle (ni espace ajouté ni trim interne) des deltas d'entrée dont `start_ms` ∈ [offset précédent, offset de la délégation) ; trimée aux deux bouts, coupée à 1 000 runes en gardant la fin ; tampon par session ≤ 4 096 runes après la dernière délégation ; deltas postérieurs avec `start_ms < offset` comptés dans `slog` (vérification à l'essai réel) ; demande vide : aucun appel d'agent, commentaire honnête. Le texte part comme `TextPart` de rôle `user` et reste une donnée non fiable (jamais injecté en instructions).

**A10 — Port `RemoteAgent` et client A2A.** `Send` renvoie `iter.Seq2[AgentUpdate, error]` (aligné sur `a2aclient`, sans goroutine d'adaptateur) ; `AgentUpdate` gagne `TaskID` et `UpdateSubmitted` ; correspondance : `submitted` → `UpdateSubmitted` ; `working` avec parts `data` → une `UpdateA2UI` par part, dans l'ordre (part non-map = invalide) ; artefact texte → `UpdateText` ; `completed` → `UpdateCompleted` ; `failed`/`rejected`/`canceled`/`input-required`/`auth-required`, flux sans état final ou `Message` direct → `UpdateFailed` (+ `CancelTask` si la tâche n'est pas terminale). Carte relue à chaque délégation (dernière carte valide gardée pour le nom) ; `AGENTS` n'accepte que `http(s)` ; l'URL de l'interface JSON-RPC de la carte doit avoir même schéma, hôte et port que l'URL configurée ; client HTTP à délai ; `ContextID` = id de session voix ; `client.Destroy()` après chaque tâche.

**A11 — Agent Qualité.** Port `Composer.Compose(ctx, Request{Text, ContextID}, Dataset) (Composition{Messages []map[string]any; Summary string}, error)` avec `ErrOutOfScope` ; JSON embarqué (`//go:embed`) = lignes brutes de `dataset.md`, KPI calculé selon la formule pondérée de la fiche (pas de valeur précalculée) ; `DATASET_PATH` supprimé (jeu embarqué seul) ; périmètre : refus explicites (autre version que 3.4, « compare », plateforme), tout le reste accepté ; mémoire bornée par `ContextID` : une 2ᵉ demande du même contexte n'émet pas de `createSurface` (seulement `updateComponents` + `updateDataModel`) ; serveur : `ReadHeaderTimeout` 5 s, `IdleTimeout`, `MaxHeaderBytes`, `http.MaxBytesReader` 64 Kio, demande coupée à 1 000 runes, contrôle de `Host` = hôte de `AGENT_PUBLIC_URL`, écoute `127.0.0.1` par défaut (`0.0.0.0` seulement avec `AGENT_LISTEN_ALLOW_NON_LOOPBACK=1`), variables `AGENT_LISTEN_ADDR`, `AGENT_PUBLIC_URL`, `A2UI_CATALOG_ID`, annulation prise en charge.

**A13 — Infra.** Réseau compose `agents: {internal: true}` ; `agent-quality` seulement sur ce réseau, sans `ports:` ; l'orchestrateur sur `default` et `agents` ; `AGENTS: http://agent-quality:<port>/.well-known/agent-card.json` ; une seule `${A2UI_CATALOG_ID:-…}` partagée ; healthcheck par sous-commande `/agent healthcheck` ; `depends_on … service_healthy` ; même durcissement (`read_only`, `cap_drop ALL`, `no-new-privileges`) ; CI en matrice sur les deux modules (vet, `-race`, `-tags acceptance`, `docker build`) ; test d'abord : script lisant `docker compose config --format json` (aucun `ports` sur l'agent, `internal: true`, `read_only`) ; instructions vocales : déléguer pour toute question sur la release, aucun chiffre avant le commentaire.

**Limites connues J2 (à écrire)** : registre, rétention et `ContextID` sont par session voix (pdr-0052 « une session par acte » vs FR-07 « l'acte 2 modifie en place les surfaces de l'acte 1 ») : Q-70 posée au porteur avant J4.
