## Contrats imposés par l'acceptation T02 (rouge attendu : `VoiceTransport`, `voiceTransportFactory`, `VoiceOrb.level` absents)
- `VoiceTransport` exporté par `feature_voice_session` : `createOfferSdp()`, `applyAnswer(sdp)`, `stop()`, `dispose()` ; `GenesisCanvasApp(config:, voiceTransportFactory:, exitHandler:)` (un transport neuf par démarrage) ; `GenesisConfig.fromEnvironment` lit `GENESIS_BACKEND_URL` ; l'app se remonte à chaque test sans état get_it résiduel.
- `VoiceOrb` (clé `voice-orb` posée sur lui-même) expose `ValueListenable<double> level` (0 = repos, niveau lissé).
- Clés : `start-button` (idle/failed), `stop-button` (dès connecting), `status-message` (absent sans message), `transcript-user`, `transcript-ai` (fragments concaténés), `agents-rail` avec une ligne `agent-<nom>` (nom, label, état « en cours » / « terminé » / « échec » / « interrompu »).
- Textes d'état (`contains`) : « injoignable », « Trop de demandes » (429), « relais » (502), « Connexion perdue », « expirée » (`closed` `expired`) ; libellés de l'assistant, à changer en bloc avec les pas si besoin.
- Séquences : arrêt normal = `[createOfferSdp, applyAnswer, stop, dispose]` avec le `DELETE` avant `stop` du transport ; échec après `createOfferSdp` = `stop` puis `dispose` une fois chacun ; `closed` reçu = aucun `DELETE` ; WSS perdu = `DELETE` puis libération, surfaces conservées ; double clic = un transport, une offre.
- **T16** : les événements d'une session précédente (ex. `onDone` du WSS de la session 1 pendant le démarrage de la 2) sont ignorés, par un compteur de génération incrémenté à `start`.
- **Livré par T16 (à connaître pour T17, T22, T23)** : séquence observable de `VoiceSession.status` : `Idle, Connecting, Active, Stopping, Failed(...)` (un échec ou une perte en `Active` passe par `Stopping` ; un échec en `Connecting` va droit à `Failed` ; un arrêt demandé donne `Stopping` puis `Idle`) ; `Active` est émis juste après le `listen` du canal (un 404 du WSS arrive donc après : `Active, Stopping, Failed(SessionClosed(null))`) ; `stop()` pendant `Connecting` attend la fin de l'étape en cours et n'est pas borné par `closeTimeout` → **T23 borne `stop()` à la sortie de l'app** ; `closeTimeout` = 8 s par défaut (T21 injecte la valeur de config ; le plan disait 7 s pour le `DELETE` du relais, 8 s pour `VoiceSession`) ; erreur non typée de `createSession` = `RelayFailed`, de `createOfferSdp` = `MicUnavailable`. `VoiceSession.envelopes` (broadcast, session courante, jamais d'erreur) alimente `LiveSessionEventSource` (T17) ; un `Failed(ConnectionLost)` devient `ChannelLost` côté événements.
