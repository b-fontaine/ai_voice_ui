Structure

Des composants en liste plate

  • Simple à générer pour un LLM : pas d'imbrication profonde
  • Rendu progressif dès que root existe ; le reste arrive ensuite

[genui-a2ui-overview] · [genui-a2ui-messages] · [ux-genui-streaming-loading]

La structure voyage à plat, et c'est le client qui reconstruit l'arbre à partir des ids. On appelle ça une liste d'adjacence : les enfants sont référencés par id, via child ou children. Au clic, « name » arrive dans un second message et l'arbre se complète. Dans l'exemple précédent tout arrivait d'un coup ; la spec permet d'étaler l'envoi. Changement depuis la v0.8 : le type est un champ plat "component": "Text", plus un objet {"Text": …}. → L'arbre est en place ; reste à savoir d'où viennent les valeurs affichées.

Séparer structure et valeurs permet de changer un chiffre sans renvoyer l'écran. Les liaisons sont des JSON Pointer ; un updateDataModel sans value supprime la clé. Un update remplace l'objet à ce chemin : un champ absent de la nouvelle valeur disparaît du rendu. Dans Genesis Canvas, les agents écrivent donc le chemin entier, /kpi, et sendDataModel vaut false. ⚠ La v1.0 RC passe à {"@path": …}, que genui 0.10.x ne comprend pas. → Le context d'une action est l'un des chemins de retour : suivons le parcours complet d'un clic.

Catalogue

Définir un composant du catalogue


final riddleCard = CatalogItem(
  name: 'RiddleCard',
  dataSchema: S.object(properties: {
    'question': S.string(description: 'La question.'),
    'answer': S.string(description: 'La réponse.'),
  }, required: ['question', 'answer']),
  widgetBuilder: (ctx) {
    final json = ctx.data as Map<String, Object?>;
    return RiddleCard(question: json['question'] as String,
                      answer: json['answer'] as String);
  },
);
final catalog = BasicCatalogItems.asCatalog()
    .copyWith(newItems: [riddleCard]);

  • schéma injecté dans le prompt
  • builder = votre widget du DS
  • catalogId : une URI, figée par surface

A2UI ne fixe pas le transport, seulement les garanties qu'il doit offrir. Délimiter, concrètement : une ligne JSONL, une frame WebSocket ou un événement SSE. Avec A2A, chaque message A2UI est une Part ; vérifié le 29/10 : JSON-RPC message/stream, A2A v0.3. Pour la voix, notre recommandation : l'A2UI passe par un canal séparé du canal de données temps réel. ⚠ La doc Flutter parle de WebSocket, mais le code de genui_a2a utilise bien SSE. → Chaque canal est aussi un point d'entrée possible : passons à la sécurité.

Sécurité

Injection de prompt et protections

Le risque d'injection

  • chaque saut est une surface : voix → orchestrateur → agents → UI
  • une consigne cachée dans une donnée (un avis client…) détourne le modèle
  • l'UI générée peut alors mentir : faux formulaire, lien piégé

Notre approche dans ce projet

  • catalogue fermé, A2UI validé deux fois : orchestrateur puis app
  • retours d'agents traités comme données non fiables
  • aucune clé dans l'app : relais SDP par le backend
  • agents isolés : réseau interne, sans clé ; modèle via une passerelle de l'orchestrateur

Ces protections ont été prévues dès l'architecture, dans une démarche Secure by Design.

[ma-prompt-injection-tools] · [genui-a2ui-security] · [p-ar-security] · [rt-ephemeral-keys] · pdr-0053 · pdr-0074

Je présente un exemple de sécurisation, sans prétendre à une garantie. Injection indirecte, dans nos données : une consigne glissée dans un extrait d'avis client. Validé veut dire composants, propriétés, liaisons et chemins ; un message refusé n'affiche aucune surface. La voix ne reçoit qu'un résumé de l'orchestrateur ; un clic n'est qu'un nom d'action et une surface. SDP : la description de session WebRTC. Le backend la relaie, donc la clé OpenAI reste sur le serveur. → Une sortie invalide n'est pas toujours une attaque : voyons comment gérer les erreurs de génération.

Erreurs et UX

Gestion des erreurs de génération

plafonner à 2 ou 3 tours opinion

  • afficher l'UI au fil de sa construction
  • chargement en 2 temps, avec un libellé
  • ne pas montrer l'erreur LLM à l'utilisateur opinion
  • message simple + étape suivante
  • confirmer avant une action importante

[genui-error-reporting] · [ux-genui-errors-validation] · [ux-genui-streaming-loading] · [ux-ai-human-in-the-loop]

Une erreur de validation est destinée au modèle, qui se corrige au tour suivant ; l'utilisateur ne la voit pas. Elle pointe le champ fautif par un JSON Pointer ; ai_voice_widget autorisait jusqu'à 20 tours de correction. Mesuré le 29/10 : hors catalogue et double création sont signalés, un update orphelin passe en silence. Dans Genesis Canvas, pas de boucle : un plan invalide bascule sur la composition déterministe. ⚠ handleMessage ne lève jamais d'exception : ses erreurs sortent par onSubmit, qu'il faut écouter. → A2UI n'est pas seul sur ce terrain : situons-le parmi les autres approches.
