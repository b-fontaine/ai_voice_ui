A2A : l'Agent Card

A2A v1.0.0 Linux Foundation · a rejoint l'AAIF (2026) SDK : Python · JS · Java · .NET · Go · Rust pas de SDK Dart officiel

  • Découverte : une URL well-known
  • supportedInterfaces : un binding par entrée, la 1re préférée
  • capabilities : streaming, push, carte étendue
  • skills : ce sur quoi l'orchestrateur route
  • Signature optionnelle : JWS sur JSON canonique (JCS)
  • Aucun secret dans la carte publique

[proto-a2a-task-lifecycle] · noms complets : TASK_STATE_*

Task : id + contextId (fil de conversation) 3 familles : actifs · interrompus (au client de répondre) · terminaux Préfixe TASK_STATE_ · UNSPECIFIED = valeur par défaut, à ne pas utiliser Terminal = définitif → nouvelle Task, même contextId Reco interne, hors spec : INPUT_REQUIRED → question vocale ou formulaire · AUTH_REQUIRED → OAuth

  • POST en application/a2a+json

Client connecté : SSE (SendStreamingMessage, SubscribeToTask) si capabilities.streaming Un objet par événement, dans l'ordre · fin = état terminal (plus de flag final en 1.0) Client déconnecté (mobile) : webhooks push, at-least-once → dédupliquer Reco interne : backend reçoit → relaie par FCM ou WebSocket Nos agents : SUBMITTED → WORKING par message A2UI → Artifact → COMPLETED Refus → REJECTED · « Stop » → CANCELED · streaming seul, pas de push

L'authentification dans A2A

App
OAuth2 code + PKCEidentité utilisateur
Orchestrateur
client credentials · mTLSidentité de service
Agents A2A

recommandation interne démo : 127.0.0.1, sans auth, agents sur réseau interne (pdr-0041)

Déclaré dans la carte

  • API key · HTTP · OAuth2 · OIDC · mTLS
  • A2A 1.0 : OAuth2 sans implicit ni password
  • Carte signée (JWS) : preuve d'origine

Appliqué par le serveur

  • Identifiant absent ou invalide → rejet
  • AUTH_REQUIRED en cours de Task
  • Carte étendue après authentification

[proto-a2a-security] · [proto-a2a-agent-card] · [proto-a2a-dart-sdk] · [p-ar-security]

securitySchemes style OpenAPI · serveur rejette identifiant absent ou invalide 5 schémas · 1.0 : retrait OAuth implicit et password, ajout Device Code Reco interne : app → orchestrateur OAuth2 code + PKCE · agents : client credentials ou mTLS SDK Dart communautaire a2a : ni auth de la spec, ni carte étendue Démo (pdr-0041) : 127.0.0.1, sans auth utilisateur, clé OpenAI au backend Agents isolés : réseau Docker interne, sans port publié, sans sortie (sauf passerelle LLM)
